# 单词弹窗：四种内容状态

日期：2026-11-08。用户明确收敛为四种状态。本版覆盖第8版中固定标准报告文案、禁止无社区时投稿、社区独立显示而不提供候选的旧规则。仅本地原型，未接真实接口或部署。

## 四种状态

| 已有固定标准映射 | 已有社区释义 | 显示与操作 |
| --- | --- | --- |
| 有 | 无 | 显示一条标准释义；“这个释义不准确”点击直接提交无内容报告；提示“这里可以提交社区释义”，提供“写一条社区释义”入口。无标签栏、无全部候选、无点赞。 |
| 无 | 有 | 显示社区释义，并提供全部标准义项供点赞。保持现有推荐／词典标签，默认社区所在推荐页；原贡献者 From、问号和 Write my own 保留。 |
| 有 | 有 | 社区在前、固定标准在后，两条都显示。无全部候选、无点赞、无标签栏。标准不准确报告仍可直接点击，社区仍用原反馈。 |
| 无 | 无 | 直接显示全部标准义项供点赞，无空推荐页、无社区区域、无标签栏。 |

“有标准”指此处已有固定 sense ID 映射；仅查到词典里的多个候选不算已有标准映射。

## 操作边界

- 已固定标准下用“这个释义不准确”，点击直接提交，不询问理由、不收集文本、不打开投稿表单，不把固定标准错误误报为词典未收录。
- 未固定候选下保留“这里没有对应的义项”，也是无内容报告；与点赞独立，不要求用户硬选。
- 标准映射错误报告与社区投稿是两个不同动作。只有标准时允许补充社区解释，不等于允许修改标准定义或添加 sense ID。
- 社区投稿是解释提交，没有“保留本地草稿”功能。原型仅演示表单，明确未实际提交，不伪装成功。
- 原有已上架解释统一归社区；新生成词典使用已有标准 sense ID 的准确位置映射。署名沿用真实原贡献者，不虚构作者。
- 👍 表示符合此处语境，不显示公开票数，成功后才显示个人选中状态；一票触发夜间核对，不以最高票直接判定正确。收藏独立。
- 标准词典由独立维护者维护；阅读器、后端及夜间巡检只选已有 ID，不创建 ID、不修改标准定义。

## 加载与失败

四种是内容组合，不是网络状态。加载、失败、真正无匹配只作必要的技术提示，不增加第五种产品内容状态，不编造候选。没有固定标准时始终查询全部合法候选，无论社区是否存在。

## 本地验证范围

组件测试覆盖四种组合、固定错误与候选无匹配回调分离、仅标准时独立社区投稿入口、社区表单不泄漏到候选页。演示验证标准固定不再返回全部候选，社区独立场景改为真实提供全部标准候选。未建设真实报告、投稿或投票服务。
